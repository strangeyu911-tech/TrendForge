# 合规与内容安全设计文档

> 配套 PRD v1.0，补齐 PRD §10「合规风险（高）」的落地设计。

---

## 1. 定位与目标

承接 PRD §10 中等级为「高」的合规风险项（敏感词库 + 政治红线规则 + 人工介入），将 PRD 中「内容合规审核覆盖 100%」与「合规风险（高）」从需求层面落地为可执行的工程设计与链路约束。

设计目标：

| 目标 | 说明 |
|------|------|
| 违规内容拦截率 100% | 命中禁发 / 高风险的内容在发布前 100% 拦截 |
| 误杀率可控 | 通过分层词库 + 人工兜底，将误杀控制在可接受区间 |
| 可审计 | 每次合规判定留痕（命中规则、处置动作、复核人） |

---

## 2. 合规分层

按风险类型与处置链路分层，覆盖从选题到发布的全链路：

| 合规层 | 主要手段 | 责任方 | 落点 |
|--------|----------|--------|------|
| 敏感词 | 分层词库匹配（禁发 / 预警 / 复审） | 算法 + 法务 | Planner 过滤 → Reviewer 扫描 |
| 政治红线 | 规则引擎 + 关键词 + 实体黑名单 + 人工 | 法务 + 人工 | Reviewer 扫描 → 人工兜底 |
| 版权 | 来源标注 + 摘要引用约束 | 编辑 + Planner | Planner 选题 → Publisher 前校验 |
| 事实 | Reviewer 事实核查 | 算法 + 编辑 | Reviewer 扫描 |

对应链路：**Planner 选题过滤 → Reviewer 合规扫描 → Publisher 发布前校验**，三层独立校验、任一层拦截即阻断。

---

## 3. 敏感词库治理

### 3.1 分层词库

| 层级 | 含义 | 处置 |
|------|------|------|
| 禁发（block） | 命中即禁止发布 | 强制 reject |
| 预警（warn） | 命中需人工 / Reviewer 关注 | 降级人工或标注 |
| 复审（review） | 疑似风险、需二次确认 | 进入人工复审队列 |

### 3.2 参考表结构

```sql
CREATE TABLE compliance_wordlist (
  wordlist_version TEXT,
  level             TEXT,     -- block | warn | review
  term             TEXT,
  category         TEXT,
  owner            TEXT,
  effective_at     TIMESTAMPTZ,
  PRIMARY KEY (wordlist_version, term)
);
```

### 3.3 更新流程（版本化）

1. 算法提议新增 / 调整词项，附理由与命中样例；
2. 法务审批词项与层级；
3. 双人发布（算法发布 + 法务确认），生成新 `wordlist_version`；
4. 旧版本保留，支持回滚与审计。

---

## 4. 政治红线规则引擎

以**规则引擎 + 关键词 + 实体黑名单**为主，不依赖黑盒 ML 分类器（监管与误杀风险）：

- 规则可解释：每条命中可定位到具体 `hit_rules`；
- 输出：

```json
{
  "risk_level": "none | low | mid | high",
  "hit_rules": ["politics_redline:entity_blacklist:xxx", "keyword:yyy"],
  "confidence": 0.0
}
```

- 置信度低或命中 mid / high → 降级人工复核，不自动放行；
- 实体黑名单由法务维护，定期更新。

---

## 5. 合规引擎 I/O 契约

输入 `article` + `review_policy`，输出统一合规判定：

```json
{
  "input": {
    "article": { "article_id": "c_xxx", "title": "...", "body": [...] },
    "review_policy": {
      "compliance_rules": ["sensitive_words_v3", "politics_redline"],
      "wordlist_version": "2026.07.21"
    }
  },
  "output": {
    "sensitive_hits": [{"level": "block", "term": "...", "position": 12}],
    "politics_risk": "none",
    "copyright_risk": "low",
    "action": "pass | revise | reject | human_review"
  }
}
```

## 6. 人工兜底 SLA

| 场景 | 处置 |
|------|------|
| 合规引擎失败 | **强制 reject** + 转人工（呼应 Agent 架构 §7.5） |
| 命中高风险（block / politics high） | 强制 reject + 人工复核，不得自动放行 |
| 高危话题（政治 / 重大灾难） | 强制人工审核（呼应 Workflow §6.1） |

人工兜底时效：高风险工单 2 小时响应，24 小时内给出处置结论。

## 7. 与 Agent / Workflow 衔接

| 落点 | 职责 | 文档呼应 |
|------|------|----------|
| Planner 选题过滤 | 选题阶段按敏感词 / 政治红线预过滤 | PRD §5.1.1 P-3 |
