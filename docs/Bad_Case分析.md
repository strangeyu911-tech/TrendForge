# Bad Case 分析与优化机制

> 配套 PRD v1.0，定义 TrendForge Bad Case 的发现、归因、修复与预防闭环。

---

## 1. 定义

**Bad Case**：发布后被判定为低质量 / 不合规 / 事实错误的内容，包括但不限于：

- 事实错误（与证据不一致或编造）；
- 严重幻觉（无中生有的人物/数据/事件）；
- 引用错误（引用与断言不匹配）；
- 合规问题（敏感词、版权、政治红线）；
- 质量低劣（逻辑混乱、重复、文不对题）；
- 体验问题（标题党、排版崩坏、字数严重偏离）；
- 用户负反馈（举报、低评分、高跳出）。

## 2. 发现渠道

| 渠道 | 触发 | 优先级 |
|------|------|--------|
| Reviewer 拦截 | 生成阶段 reject | P0（未发布） |
| 发布后审核巡查 | 定时抽检 | P1 |
| 用户举报 | C 端举报按钮 | P0 |
| 数据异常 | CTR/完读率低于阈值 | P1 |
| 舆情监控 | 外部负面提及 | P0 |
| 合规扫描 | 定时全量扫描 | P0 |

## 5. 闭环流程

```
   发现 ──► 标注 ──► 归因 ──► 修复 ──► 验证 ──► 沉淀
                                       │
                                       ▼
                                   回归测试集
```

### 5.1 标注

- Reviewer 拦截的 Bad Case 自动标注（带分类建议）；
- 用户举报/巡查的由人工标注；
- 标注双盲抽检（10% 复核）保证质量。

### 5.2 归因

按"5 Why"逐层定位根因：

```
现象：文章称 GPT-6 参数 10T
Why1：Writer 输出了错误数据
Why2：Writer Prompt 没要求关键数据二次核对
Why3：v1.3.0 升版时未加此约束
Why4：Prompt 评审清单缺少"关键数据约束"项
Why5：评审清单维护不及时
```

根因：Prompt 评审流程缺失关键数据约束项 → 修复点：评审清单 + Prompt 模板。

### 5.3 修复

按根因分派：

| 根因类型 | 修复动作 | 责任人 |
|----------|----------|--------|
| Prompt 缺陷 | 起新版 + 评估 + A/B | 算法 |
| RAG 召回不足 | 补源 / 调切分 / 调权重 | 算法 |
| Reviewer 漏检 | 加强规则 / 加 case | 算法 |
| 数据源错误 | 切源 / 标记不可信 | 数据 |
| 流程缺陷 | 改 SOP | 产品 |
| 合规规则缺失 | 补规则 | 法务 + 算法 |

### 5.4 验证

- 修复后必须跑回归测试集（含该 Bad Case + 同类历史 case）；
- 回归通过 + A/B 验证才关闭；
- 关闭后该 case 进入"预防案例库"。

### 5.5 沉淀

- 严重 Bad Case 写入 Prompt Few-shot 反例库；
- 同类问题归因写入知识库；
- 月度 Bad Case 复盘会；
- 季度更新分类体系与评审清单。

---

## 6. 回归测试集

### 6.1 构建方式

- 每个已关闭的 Bad Case 抽取为测试 case；
- case 包含 input + 期望"不犯同样错误"；
- 按分类标签管理。

### 6.2 使用

- Prompt 升版前必跑回归集；
- 回归集失败 ≥ 1 case 即阻止升版；
- 回归集随 Bad Case 增长滚动扩充。

### 6.3 规模目标

- 每个 Agent 场景回归集 ≥ 100 case；
- 覆盖所有一级分类；
- 每月新增 case ≥ 10。

## 7. 典型 Bad Case 案例库

> 以下为示例性案例（基于真实 AI 内容生产常见问题抽象）。

### 案例 1：数据幻觉（H02）

**现象**：财经稿件引用"某机构预测 2026 年 Q3 GDP 增速 5.8%"，但该机构从未发布此数据。

**根因**：Writer Prompt 未强制要求数字必须有 evidence_id；Research 召回的片段中无此数据，Writer 自行脑补。

**修复**：
- Prompt 增加"所有数字必须带 [ev_xxx] 引用，无引用数字直接拒绝"；
- Reviewer 增加数字引用校验规则；
- 该案例入回归集。

### 案例 2：引用不匹配（C01）

**现象**：文章断言"A 公司营收增长"，引用的却是"B 公司财报"。

**根因**：Writer Prompt 仅要求有引用，未校验引用内容与断言的相关性。

**修复**：
- Prompt 增加"引用段落须与断言主题一致"约束；
- Reviewer 增加引用相关性校验（LLM judge）。

### 案例 3：标题党（U01）

**现象**：标题"震惊！这家公司一夜破产"，正文实为常规财报分析。

**根因**：Prompt 模板鼓励"吸睛标题"，未限制夸张措辞。

**修复**：
- Prompt 标题约束改为"准确概括核心事实，禁止夸张词（震惊/惊呆/必看）"；
- Reviewer 增加标题党检测；
- 标题词表黑名单。

### 案例 4：合规红线（G02）

**现象**：国际新闻稿件涉及敏感地缘表述。

**根因**：Planner 选题未过滤，Reviewer 合规规则未覆盖该表述。

**修复**：
- Planner 选题阶段增加地缘敏感词过滤；
- Reviewer 合规词表更新；
- 该类话题强制人工审核。

### 案例 5：低完读率（D02）

**现象**：内容 CTR 正常但完读率 < 10%（品类 P10 = 25%）。

**根因**：文章开头铺垫过长，核心信息在文末。

**修复**：
- Prompt 增加"开头 50 字内必须出现核心事实"（即 A/B 实验 v2.0.1）；
- 数据回流持续监控。

## 8. 量化目标

| 指标 | 基线 | 目标 |
|------|------|------|
| Bad Case 率（发布后） | 8% | ≤ 3% |
| 严重 Bad Case（F/H/G）率 | 2% | ≤ 0.5% |
| Bad Case 平均修复时长 | 5 天 | ≤ 2 天 |
| 回归测试通过率 | - | ≥ 99% |
| 同类 Bad Case 复发率 | 15% | ≤ 3% |

## 10. 组织保障

- **Bad Case Owner**：每条 Bad Case 有明确责任人；
- **SLA**：严重级 2 小时响应、24 小时修复；major 1 天响应、3 天修复；
- **复盘机制**：严重级必复盘，输出根因报告；
- **激励机制**：发现高质量 Bad Case 计入绩效；
- **知识沉淀**：所有修复经验进知识库，季度汇总成《Prompt 最佳实践》。
