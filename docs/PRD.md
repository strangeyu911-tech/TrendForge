## 1. 项目背景与目标

### 1.1 背景

- **行业现状**：全球热点新闻（科技 / 财经 / 国际 / 娱乐）从事件发生到内容生产的窗口期被压缩到分钟级，传统人工采编难以兼顾速度、覆盖广度与多语言分发。
- **技术机会**：大模型 + Multi-Agent + RAG 的组合已具备"端到端内容生产"能力，可在保证事实准确性的前提下，将热点内容生产周期从小时级压缩到分钟级。
- **痛点**：
  - 内容平台人工编辑成本高、覆盖源有限；
  - 现有"AI 写稿"系统事实幻觉严重，缺乏可追溯的 RAG 与审核闭环；
  - Prompt 调优缺乏版本管理与实验机制，效果难以沉淀；
  - 缺少从 CTR / 阅读率 / Prompt 效果等数据回流到生产侧的闭环。

### 1.2 目标（OKR 形式）

**O：构建业内领先的 AI Native 全球热点内容生产闭环**

| 序号 | KR | 衡量方式 |
|------|----|----------|
| KR1 | 热点从触发到内容发布平均时延 ≤ 8 分钟 | Workflow 日志 P50 |
| KR2 | 生成内容事实错误率 ≤ 2% | Reviewer 标注 + 人工抽检 |
| KR3 | AI 生成内容 CTR 较人工基线提升 ≥ 15% | A/B 实验置信区间 |
| KR4 | 单条内容生产成本 ≤ 人工的 1/5 | 资源账单核算 |
| KR5 | Prompt 优化迭代周期 ≤ 3 天/轮 | Prompt 管理平台记录 |

### 1.3 非目标（Non-Goals）

- 不做 UGC 内容社区；
- 不做原创深度调查报道（依赖人工记者）；
- 不做长视频/直播生产；
- 本期不覆盖图像/视频生成（仅文本 + 封面图）。

## 3. 用户画像与场景

### 3.1 用户画像

| 角色 | 诉求 | 关键场景 |
|------|------|----------|
| 内容运营（P0） | 快速铺量、多端分发、效果可追踪 | 配置选题策略、监控看板、干预 Bad Case |
| 内容编辑（P0） | 审核把关、调优 Prompt、人工兜底 | 审核队列、Prompt 实验台、Bad Case 标注 |
| 算法工程师（P1） | Agent 与 RAG 调优、A/B 设计 | Agent 配置、检索召回评估、实验分析 |
| 数据分析师（P1） | 指标体系搭建、归因分析 | SQL 看板、漏斗分析、实验报告 |
| C 端读者（P2） | 及时、准确、可读的热点内容 | 阅读内容、点赞/评论/分享 |

### 3.2 核心场景

**场景 1：突发热点自动生产**
某科技公司发布新品 → Planner 30 秒内识别热点 → Research 检索多源信息 → Writer 生成多语言稿件 → Reviewer 事实核查 → Publisher 多端发布。端到端 ≤ 8 分钟。

**场景 2：Prompt A/B 迭代**
编辑发现财经类内容 CTR 下降 → 在 Prompt 实验台发起 v1 vs v2 对照实验 → 系统按流量分桶 → 7 天后数据看板给出显著性结论 → 胜出版本自动升级为生产版本。

**场景 3：Bad Case 闭环**
Reviewer 拦截一篇事实错误稿件 → 标记为 Bad Case 并归类 → 触发 Prompt 优化任务 → 修复后回归测试通过 → 关闭 Bad Case。

## 4. 需求概述

### 4.1 系统全景

系统由五大子系统构成：

1. **Multi-Agent 子系统**：Planner / Research / Writer / Reviewer / Publisher
2. **RAG 子系统**：实时新闻知识库 + 语义检索
3. **Prompt Engineering 子系统**：版本管理 + A/B 实验
4. **Workflow 子系统**：编排 + 异常处理 + 回退
5. **数据子系统**：SQL 分析 + 看板 + 回流

### 4.2 功能模块清单

| 模块 | 子功能 | 优先级 |
|------|--------|--------|
| Multi-Agent | Planner 选题 / Research 检索 / Writer 生成 / Reviewer 审核 / Publisher 发布 | P0 |
| RAG | 实时新闻接入 / 向量化 / 检索召回 / 重排 | P0 |
| Prompt | 版本管理 / A/B 实验 / 灰度发布 | P0 |
| Workflow | 流程编排 / 异常重试 / 人工介入 / 回退 | P0 |
| 数据 | CTR / 阅读率 / Prompt 效果 / Bad Case | P0 |
| 监控 | 全链路 Trace / 成本核算 / 告警 | P1 |
| 多语言 | 中/英/日/韩 生成与翻译 | P1 |
| 多模态 | 封面图生成（下一期） | P2 |

## 5. 详细功能需求

### 5.1 Multi-Agent 子系统

> 详细设计见 `Agent架构设计.md`，本节给出需求侧定义。

#### 5.1.1 Planner（选题策划与任务分配）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| P-1 | 接入多源热点信号（搜索热榜、社媒趋势、新闻 RSS） | 信号源 ≥ 5 个，刷新频率 ≤ 5 分钟 |
| P-2 | 输出选题列表，含话题、热度分、建议角度、目标语言 | 每字段非空，热度分有计算依据 |
| P-3 | 按内容策略过滤（敏感词、版权、已发布去重） | 命中策略 100% 过滤 |
| P-4 | 任务分配到下游 Agent，含优先级与 SLA | 任务可追溯，SLA 超时告警 |

#### 5.1.2 Research（热点检索与信息收集）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| R-1 | 调用 RAG 检索 + 实时 Web 检索，召回 ≥ 20 条相关片段 | 召回率 ≥ 85%（标注集） |
| R-2 | 输出结构化证据集合（来源、时间、可信度、引用片段） | 每条证据可溯源到 URL |
| R-3 | 多语言源检索并归一化为工作语言 | 翻译保留原文链接 |
| R-4 | 证据冲突时标注并降权 | 冲突标记字段必填 |

#### 5.1.3 Writer（内容生成）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| W-1 | 基于 Research 证据生成结构化稿件（标题/正文/摘要/标签） | 结构完整、字数符合模板 |
| W-2 | 强制引用证据 ID，未引用不通过 Reviewer | 引用覆盖率 100% |
| W-3 | 支持多模板（快讯/深度/盘点/图表解读） | 模板可配置 |
| W-4 | 支持多语言输出 | 中/英/日/韩 各 1 套模板 |

#### 5.1.4 Reviewer（质量审核与事实核查）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| RV-1 | 事实核查：逐条校验引用与证据一致性 | 一致率 ≥ 98% |
| RV-2 | 质量打分：可读性 / 客观性 / 完整性 / 时效性 | 四维评分输出 |
| RV-3 | 合规审核：敏感词、版权、政治红线 | 命中即拦截 |
| RV-4 | 不通过则回退 Writer 并附修改建议 | 回退链路可追溯 |

#### 5.1.5 Publisher（内容发布与分发）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| PB-1 | 多渠道发布（站内 feed / 微博 / Twitter / RSS） | 渠道 ≥ 3 |
| PB-2 | 灰度发布：先小流量观察 CTR，达标后全量 | 灰度策略可配 |
| PB-3 | 发布元数据回写（渠道、时间、版本、Prompt 版本） | 元数据完整 |
| PB-4 | 撤回机制：发现严重问题 5 分钟内全网撤回 | 撤回成功率 100% |

### 5.2 RAG 子系统

> 详细设计见 `RAG知识库设计.md`。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| RG-1 | 实时新闻源接入（RSS / API / 爬虫） | 接入源 ≥ 10，延迟 ≤ 5 分钟 |
| RG-2 | 文档切分、去重、向量化入库 | 切分粒度可配，去重率 ≥ 95% |
| RG-3 | 混合检索（向量 + BM25 + 时间衰减） | nDCG@10 ≥ 0.7 |
| RG-4 | 引用溯源：每个召回片段带原始 URL 与时间 | 100% 可溯源 |
| RG-5 | 知识库冷启动 + 持续增量更新 | 增量 T+0 |

### 5.3 Prompt Engineering 子系统

> 详细设计见 `Prompt版本管理方案.md`。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| PE-1 | Prompt 版本管理：语义化版本号 + 不可变快照 | 版本可回滚 |
| PE-2 | 变量模板（Jinja2）+ 多语言变体 | 模板渲染正确 |
| PE-3 | A/B 实验：流量分桶 + 显著性检验 | p-value 输出 |
| PE-4 | 灰度发布：按比例放量 | 比例误差 ≤ 1% |
| PE-5 | 效果回流：每版本绑定 CTR / 阅读率 / Bad Case | 指标自动归因 |

### 5.4 Workflow 子系统

> 详细设计见 `Workflow设计.md`。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| WF-1 | DAG 编排：热点发现→检索→生成→审核→发布 | 流程可视化 |
| WF-2 | 异常重试（指数退避）+ 死信队列 | 重试 ≤ 3 次 |
| WF-3 | 人工介入节点（高危选题需人工确认） | 介入记录留痕 |
| WF-4 | 回退机制（Reviewer 不通过回 Writer） | 回退 ≤ 2 次，超限转人工 |
| WF-5 | 全链路 Trace（每步输入输出、耗时、Token） | Trace 可查询 |

### 5.5 数据子系统

> 详细设计见 `SQL数据看板设计.md`。

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| DA-1 | 事件埋点：曝光 / 点击 / 阅读 / 完读 / 互动 | 埋点完整率 ≥ 99% |
| DA-2 | CTR / 阅读率 / 完读率 / Prompt 效果看板 | 看板 T+10 分钟刷新 |
| DA-3 | 漏斗分析：选题→发布→曝光→点击 | 漏斗可下钻 |
| DA-4 | A/B 实验报告自动生成 | 含 p-value 与置信区间 |
| DA-5 | Bad Case 归因看板 | 根因分类统计 |

## 8. 数据指标体系

### 8.1 北极星指标

**AI 生成内容的总阅读时长 / 总曝光量**（人均阅读深度）

### 8.2 指标分层

| 层级 | 指标 |
|------|------|
| L1 业务 | DAU、内容消费时长、AI 内容占比 |
| L2 生产 | 生产量、生产时延、通过率、Bad Case 率 |
| L3 分发 | 曝光量、CTR、阅读率、完读率、互动率 |
| L4 算法 | 召回率、引用一致率、Prompt 版本效果 |
| L5 成本 | Token 成本、单条成本、ROI |

## 10. 风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 事实幻觉 | 高 | 强制引用 + Reviewer 核查 + Bad Case 闭环 |
| 合规风险 | 高 | 敏感词库 + 政治红线规则 + 人工介入 |
| 新闻源版权 | 中 | 仅引用摘要 + 标注来源 + 公共源优先 |
| LLM 成本超支 | 中 | 模型分级（draft/quality）+ 缓存 |
| 单点故障 | 中 | Agent 无状态化 + 队列解耦 |
| Prompt 漂移 | 低 | 版本不可变 + 实验对照 |
